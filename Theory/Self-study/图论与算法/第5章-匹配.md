# 第 5 章 匹配

**匹配（matching）**解决的是一类很朴素、也极常见的资源分配问题：

- 一个人最多接一项任务，一项任务最多交给一个人；
- 两两组队时，一个人不能进两支队；
- 左侧是申请者，右侧是岗位，每个岗位只能录取一人。

把对象画成顶点、允许的配对画成边。接下来不再问“能不能连通”，而是问：**能同时选出多少条互不抢端点的边？**

本章默认讨论简单无向图。二分图的两个部分记为 `X` 和 `Y`。

---

## 5.1 匹配和最大匹配

### 1. 匹配、极大匹配、最大匹配

给定图 `G = (V, E)`，边集 `M ⊆ E` 若其中任意两条边都不相邻（不共享端点），`M` 就是 `G` 的一个**匹配**。

- 匹配边的端点称为被 `M` **饱和**，也常说“已匹配”。
- 没有被匹配边碰到的顶点称为**未饱和**或“未匹配”。
- **极大匹配（maximal matching）**：不能再直接往 `M` 加一条边，仍保持匹配。
- **最大匹配（maximum matching）**：在所有匹配中，边数最多。

最容易混淆的是“极大”和“最大”：

```text
极大：不能直接继续塞边了。
最大：全局里边数已经最多。
```

例如路径 `0 - 1 - 2 - 3`：

- `{(1, 2)}` 是极大匹配：剩下的边都和它相邻，不能直接加。
- 但它不是最大匹配，因为 `{(0,1), (2,3)}` 有两条边。

因此，贪心地随便选一条还能选的边，只保证得到**极大**匹配，不能保证最大匹配。

一些可立即判断的结论：

- 阶为 `n` 的图，最大匹配至多有 `floor(n / 2)` 条边；
- `K_n` 的最大匹配大小是 `floor(n / 2)`；
- 完全二分图 `K_{m,n}` 的最大匹配大小是 `min(m, n)`。

### 2. 两个匹配的对称差

两个边集的**对称差**：

```text
M Δ N = (M \ N) ∪ (N \ M)
```

即“只保留恰好属于其中一个集合的边”。若 `M` 和 `N` 都是匹配，则由 `M Δ N` 导出的每个非平凡连通分支，只可能是：

- 一条交替路；或
- 一个偶圈。

原因是每个顶点至多接一条 `M` 边和一条 `N` 边，度数不可能超过 2；沿着分支走，边自然在 `M` 与 `N` 间交替。

这个结构事实是增广路定理的幕后骨架。

### 3. 交替路与增广路

相对于当前匹配 `M`：

- **`M` 交替路**：路径上的边在 `M` 与 `E \ M` 中交替出现。
- **`M` 增广路**：一条非平凡交替路，起点和终点都未被 `M` 饱和。

增广路一定以“不在 `M` 中的边”开始和结束，因此它含有的非匹配边比匹配边多 1 条。

例如当前 `M = {(a, 1)}`，并有路径：

```text
b -- 1 == a -- 2
```

其中 `==` 表示匹配边 `(a,1)`，普通连线表示非匹配边。`b - 1 - a - 2` 的两端 `b、2` 未匹配，所以它是增广路。

把路径上的边“翻转”即可：原本在 `M` 中的删掉，原本不在 `M` 中的加入。

```text
{(a, 1)}
    Δ {(b, 1), (a, 1), (a, 2)}
= {(b, 1), (a, 2)}
```

匹配大小从 1 变成 2。这里的 `Δ` 正是对称差操作。

### 4. 贝尔热定理：最大匹配的判据

> **贝尔热定理**：匹配 `M` 是最大匹配，当且仅当图中不存在 `M` 增广路。

#### 为什么“有增广路”就不可能最大

刚才已经看见了：沿增广路做对称差，匹配边数净增 1。因此只要还能找到增广路，当前答案就还能变大。

#### 为什么“没有增广路”就已经最大

反过来，假设存在更大的匹配 `N`。观察 `M Δ N` 的各个交替路和偶圈：偶圈中两种边数量相同；若 `N` 的边总数更多，那么某条交替路上 `N` 边一定比 `M` 边多一条。这条路的两端就都不被 `M` 匹配，正是一条 `M` 增广路，矛盾。

所以最大匹配不靠猜，而靠一个很稳定的循环：

```text
不断寻找增广路 -> 找到就翻转 -> 直到找不到。
```

## 5.1.2 二分图最大匹配

二分图中，每条边都从 `X` 连到 `Y`。这让寻找增广路可以始终从 `X` 中未匹配的顶点出发，沿着：

```text
非匹配边 X -> Y，匹配边 Y -> X，非匹配边 X -> Y，...
```

前进。下面三个算法都围绕这件事，只是效率越来越高。

### 1. Kuhn 算法（教材称“匈牙利算法”）

#### 核心思想

从一个未匹配的左侧顶点 `u` 出发，用 DFS 尝试找一条增广路。

看到右侧顶点 `v` 时：

1. 若 `v` 目前未匹配，路径到达一个未匹配终点，可以把当前路径翻转。
2. 若 `v` 已匹配给某个左侧顶点 `u2`，就尝试为 `u2` 另找一个右侧顶点；若成功，`v` 就可以腾给 `u`。

“腾位置”是这段算法的灵魂。它不是贪心地只找空位，而是允许沿已有匹配递归重排。

#### Python 实现

```python
def maximum_bipartite_matching(left_adj, right_size):
    """
    Kuhn 算法，求二分图最大匹配。

    left_adj[u] 是左侧顶点 u 可以连接的右侧顶点列表。
    左侧编号为 0 到 len(left_adj) - 1，右侧编号为 0 到 right_size - 1。

    返回 (matching_size, match_left, match_right)：
    - match_left[u] = 与 u 匹配的右侧顶点；-1 表示未匹配。
    - match_right[v] = 与 v 匹配的左侧顶点；-1 表示未匹配。
    """
    left_size = len(left_adj)
    match_right = [-1] * right_size

    def find_augmenting_path(left_vertex):
        """尝试从一个左侧顶点出发，为它找到可增广的位置。"""
        for right_vertex in left_adj[left_vertex]:
            if seen_right[right_vertex]:
                continue

            # 同一轮 DFS 中，一个右侧点只尝试一次，避免在交替路中绕圈。
            seen_right[right_vertex] = True
            previous_left = match_right[right_vertex]

            # 右侧点空闲，或能为原配对者另找位置：都可以把它让给当前点。
            if previous_left == -1 or find_augmenting_path(previous_left):
                match_right[right_vertex] = left_vertex
                return True

        return False

    matching_size = 0

    for left_vertex in range(left_size):
        # 每次寻找一条新增广路，都要重新建立本轮的访问记录。
        seen_right = [False] * right_size

        if find_augmenting_path(left_vertex):
            matching_size += 1

    match_left = [-1] * left_size
    for right_vertex, left_vertex in enumerate(match_right):
        if left_vertex != -1:
            match_left[left_vertex] = right_vertex

    return matching_size, match_left, match_right
```

#### 变量怎样对应增广路

- `match_right[v]` 表示当前匹配中 `v` 的搭档。只存右侧的搭档就足以做“腾位置”。
- `find_augmenting_path(u)` 的递归链，正是在走交替路：从左到右走一条未匹配边，再从右回到它原来的左侧搭档。
- 递归成功回退时，`match_right[right_vertex] = left_vertex` 会逐层反向改写搭档，等价于对整条增广路取对称差。
- `seen_right` 必须**每轮增广重新清空**；若放在所有轮次共用，会错误地阻止后来的增广路访问右侧点。

#### 手算一个“腾位置”过程

设：

```text
L0 -> R0, R1
L1 -> R0
```

先处理 `L0`，得到 `(L0, R0)`。处理 `L1` 时，`R0` 已被 `L0` 占用；算法递归为 `L0` 找路，发现 `R1` 空闲，于是把 `L0` 改配到 `R1`，再把 `R0` 配给 `L1`。

最终得到两条匹配边：`(L0, R1)、(L1, R0)`。如果只看“R0 被占了”，贪心就会错过这个答案。

#### 复杂度与限制

教材的分析是：最多增广 `O(n)` 次，每一轮用 DFS 找增广路要 `O(n + m)`，总时间为：

```text
O(n(n + m))
```

它只适用于**二分图**。在含奇圈的一般图里，简单地沿交替路 DFS 可能因为走到奇圈而做出错误选择；这正是后面花算法要解决的问题。

### 2. Hopcroft-Karp 算法

Kuhn 算法每次只增广一条路。Hopcroft-Karp 的两处改进是：

1. 用多源 BFS 找到当前最短增广路所在的层；
2. 在这些最短层中，一次找出多条彼此顶点不相交的增广路，同时增广。

这和你在多源 BFS 中把所有起点同时入队是同一种视角：本轮所有左侧未匹配顶点一起出发，不让某一条 DFS 路过早决定全局。

#### Python 实现

```python
from collections import deque


def hopcroft_karp(left_adj, right_size):
    """
    Hopcroft-Karp 算法，求二分图最大匹配。
    输入和返回格式与 maximum_bipartite_matching 相同。
    """
    left_size = len(left_adj)
    match_left = [-1] * left_size
    match_right = [-1] * right_size
    infinity = float("inf")

    def bfs_layers():
        """从全部未匹配左侧点多源 BFS，建立最短增广路的分层。"""
        queue = deque()

        for u in range(left_size):
            if match_left[u] == -1:
                distance[u] = 0
                queue.append(u)
            else:
                distance[u] = infinity

        shortest_augmenting_length = infinity

        while queue:
            u = queue.popleft()

            # 已经到达更短的未匹配右侧点后，不再扩展更深层。
            if distance[u] >= shortest_augmenting_length:
                continue

            for v in left_adj[u]:
                next_left = match_right[v]

                if next_left == -1:
                    shortest_augmenting_length = distance[u] + 1
                elif distance[next_left] == infinity:
                    # 从右侧 v 沿匹配边回到它的左侧搭档。
                    distance[next_left] = distance[u] + 1
                    queue.append(next_left)

        return shortest_augmenting_length != infinity, shortest_augmenting_length

    def dfs_augment(u, shortest_augmenting_length):
        """只沿 BFS 分层向前，寻找一条最短增广路。"""
        for v in left_adj[u]:
            next_left = match_right[v]

            if next_left == -1:
                # 到未匹配右侧点时，整条路必须恰好是本轮最短长度。
                if distance[u] + 1 == shortest_augmenting_length:
                    match_left[u] = v
                    match_right[v] = u
                    return True

            elif distance[next_left] == distance[u] + 1:
                if dfs_augment(next_left, shortest_augmenting_length):
                    match_left[u] = v
                    match_right[v] = u
                    return True

        # 此点在本轮无法继续增广，标为无穷以免重复探索失败分支。
        distance[u] = infinity
        return False

    matching_size = 0
    distance = [infinity] * left_size

    while True:
        found_path, shortest_length = bfs_layers()
        if not found_path:
            break

        for u in range(left_size):
            if match_left[u] == -1:
                if dfs_augment(u, shortest_length):
                    matching_size += 1

    return matching_size, match_left, match_right
```

#### 这段代码在做什么

`bfs_layers()` 不直接改匹配，它只回答：“当前还能增广的话，最短增广路有几层；哪些左侧点在这些层上？”

`dfs_augment()` 则只允许沿着 `distance` 增加的方向走，因此不会拿一条更长的路破坏本轮的分层结构。每成功一条路都会立即翻转匹配；同一轮之后的 DFS 会绕过已占用的顶点，于是得到的一组增广路彼此不相交，可以安全地同时生效。

教材用 `d'` 记录本轮第一次发现未匹配右侧点时的距离；它随着轮数严格递增。由此可证明总轮数为 `O(sqrt(n))`，每轮处理图一次 `O(n + m)`，所以：

```text
O(sqrt(n) * (n + m))
```

它仍然只用于二分图。通常做题时，规模不大、想快速写对，用 Kuhn 已很够；二分图顶点和边很多时，再考虑 Hopcroft-Karp。

### 3. 非二分图：花算法的必要性

对于一般图，Kuhn 和 Hopcroft-Karp 都不能直接保证正确。麻烦来自**奇圈**：一条交替搜索可能走到一个奇长度的交替圈，之后“先走哪条边”会影响能否发现本来存在的增广路。

花算法（Blossom algorithm）的核心处理是：

1. 在交替搜索中识别一个奇圈，称为**花**；
2. 把整朵花临时收缩为一个超级顶点；
3. 在缩小后的图继续找增广路；
4. 若路径经过超级顶点，再把它还原，选择花内正确的交替路径。

收缩不是把问题糊弄掉，而是把“奇圈内部的二义性”封装起来。教材给出了这个思想和运行示意，没有展开可直接照写的伪代码；完整可靠的实现细节很多，当前不建议死背。你需要掌握的是：

> 二分图没有奇圈，所以普通交替 BFS/DFS 足够；一般图有奇圈，所以必须处理花收缩。

教材给出的朴素花算法复杂度为 `O(n^2(n + m))`；采用更合适的数据结构可降到 `O(n^3)`。

## 5.2 完美匹配

### 1. 定义与必要条件

匹配 `M` 若饱和图中**所有顶点**，称为**完美匹配（perfect matching）**。

它意味着每个顶点都恰好有一个搭档。于是：

- 完美匹配一定是最大匹配；
- 最大匹配不一定完美匹配；
- 图的顶点数必须是偶数，但“顶点数偶数”只是必要条件，远远不够。

例如 4 个顶点的星形图有偶数个顶点，却不可能完美匹配：中心最多只能配给一个叶子，剩下叶子无处可去。

### 2. 邻点集与霍尔定理

对顶点集 `S`，它的**邻点集** `N(S)` 是 `S` 中所有顶点的全部邻点组成的集合。

对于二分图 `G = (X ∪ Y, E)`，霍尔定理给出“能否让 `X` 中所有顶点都被匹配”的充要条件：

> 对任意 `S ⊆ X`，都有 `|N(S)| >= |S|`。

直觉非常直接：`S` 里的每个点都要找不同对象；它们可接触的右侧顶点总数至少得有这么多，否则必然有人没位置。

这叫**霍尔条件**。它不仅必要，还是充分的；充分性的证明比直觉深一些，但做题时可把它当作可靠判据。

如果 `|X| = |Y|`，霍尔条件保证 `X` 全部被饱和时，匹配也必然饱和 `Y`，因此就是完美匹配。

### 3. 用最大匹配代码检查二分图完美匹配

不需要显式枚举霍尔条件的所有子集。算法题中通常直接求最大匹配：若匹配大小等于两侧顶点数，就有完美匹配。

```python
def has_perfect_bipartite_matching(left_adj, right_size):
    """判断二分图是否存在完美匹配。"""
    left_size = len(left_adj)

    # 完美匹配要求两侧顶点数量先相等。
    if left_size != right_size:
        return False

    matching_size, _, _ = hopcroft_karp(left_adj, right_size)
    return matching_size == left_size
```

这里的代码并不是替代霍尔定理，而是把霍尔定理保证“存在性”的问题，交给增广路算法实际构造出来。

### 4. 一般图中的完美匹配：塔特定理

二分图有霍尔定理；任意图有更一般的**塔特定理**。

记 `o(H)` 为图 `H` 中奇数阶连通分支的数量。对任意顶点集 `S ⊆ V`，删掉 `S` 后观察 `G - S`：

> 图 `G` 有完美匹配，当且仅当对任意 `S ⊆ V`，都有 `o(G - S) <= |S|`。

为什么这个条件至少是必要的？`G - S` 的每个奇数阶连通分支，内部不可能全靠两两配对覆盖完，总有一个顶点必须跨出去和 `S` 中某个顶点配对；而 `S` 中每个顶点最多只能配一次，所以奇分支数量不能超过 `|S|`。

霍尔定理和塔特定理可以互相推出。你暂时不必证明它们，但要看出共同主题：**完美匹配的障碍，往往不是单个点没邻居，而是一批点或一批奇分支在争抢太少的外部资源。**

## 本章算法选择表

| 图的类型与目标 | 优先方法 | 关键条件 |
| --- | --- | --- |
| 二分图，规模中小，求最大匹配 | Kuhn / 匈牙利算法 | 用 DFS 找一条增广路 |
| 二分图，规模较大，求最大匹配 | Hopcroft-Karp | BFS 分层 + 同轮多条最短增广路 |
| 一般图，求最大匹配 | 花算法 | 必须处理奇圈收缩 |
| 二分图，判断能否完美匹配 | 最大匹配或霍尔定理 | 两侧大小相等且匹配覆盖一侧 |
| 一般图，判断能否完美匹配 | 塔特定理 | 检查删点后的奇分支数量 |

## 易错点

1. **把极大匹配当成最大匹配。**
   不能再加一条独立边，不代表不能通过重排现有匹配得到更多边；增广路就是重排的证据。

2. **把“找到未匹配右侧点”当成唯一情况。**
   右侧点已匹配不代表死路，应该递归尝试给它原来的左侧搭档另找位置。

3. **Kuhn 中 `seen_right` 不在每轮重置。**
   访问标记只用于避免同一次 DFS 绕圈；下一条增广路仍应允许重新尝试那些右侧顶点。

4. **在非二分图上直接套 Kuhn。**
   奇圈会破坏二分图交替搜索的层次结构，需要花算法。

5. **以为顶点数为偶数就必有完美匹配。**
   偶数只是必要条件；星形图就是反例。二分图看霍尔条件，一般图看塔特条件。

6. **把 `N(S)` 理解成只统计 `S` 外的某个单点邻居。**
   `N(S)` 是整个集合 `S` 的邻点并集，并且按集合去重。

## 本章收束

匹配的核心不是“挑边”，而是维护一组互不冲突的配对，并不断寻找能让它**净增一条边**的增广路。

- 贝尔热定理告诉你：没有增广路，才是真的最大。
- Kuhn 用 DFS 一条条找增广路；Hopcroft-Karp 用多源 BFS 把最短增广路成批处理。
- 二分图没有奇圈，所以问题干净；一般图需要花算法收缩奇圈。
- 完美匹配把目标提高到“一个点也不能剩”，霍尔定理和塔特定理揭示了它背后的资源瓶颈。

以后遇到“人-任务、学生-课程、左侧对象与右侧资源一一分配、两两组队”这类题，先问一句：**每个对象是否最多用一次？如果是，先把它建成匹配问题，再去找增广路。**
