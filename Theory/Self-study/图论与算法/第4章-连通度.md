# 第 4 章 连通度

第 2 章问的是：图现在是否连通？本章再追问一步：**它有多抗破坏？**

如果一条铁路网删掉一条边就会断，它虽然连通，却非常脆弱；若必须同时关闭多条线路或多个城市，网络才会断开，它的连通度就更高。这里的关键词是：**块、点割集、边割集、点连通度、边连通度，以及门格尔定理。**

本章默认讨论简单无向图。设图 `G = (V, E)`，顶点数为 `n`，边数为 `m`。

---

## 4.1 块

### 1. 为什么需要“块”

第 2 章已经学过割点：删除一个顶点后，图的连通分支增多，这个顶点就是网络的单点故障。

但一个大图往往不是整体脆弱，而是由若干个结实的小区域通过割点串在一起。例如两个环共用一个顶点：每个环内部都能绕路，只有共享顶点是薄弱连接。**块（block）就是把这些“内部没有割点、已经不能再扩张”的结实区域拆出来。**

### 2. 块的定义

图 `G` 的一个**块**，是 `G` 的一个**极大的、没有割点的连通子图**。

- 连通：块内部任意两点可达。
- 没有割点：删掉块内任意一个顶点，块不会因此断开。
- 极大：不能再加入 `G` 中的顶点或边，仍保持上面两条性质。

这里的“极大”是指**按包含关系不能再扩大**，不是“顶点数最多”。

几个立即可用的例子：

| 图或子图 | 是不是块 | 原因 |
| --- | --- | --- |
| `K_n (n >= 3)` | 是 | 删除一个点后仍连通 |
| 圈 `C_n` | 是 | 任意两点之间有两侧可走 |
| 树中的一条边 `u-v` | 是 | `K_2` 本身没有割点，且不能扩成更大的无割点连通子图 |
| 孤立顶点 | 是 | 单点连通且没有割点 |
| 一棵有至少两条边的树整体 | 否 | 内部顶点是割点 |

因此，树的块正是一条条单边；不要把“块”误解成一定包含圈。

### 3. 块与圈：八个等价刻画

对于阶至少为 3 的连通图 `G`，下面的说法等价；满足任意一条，就说明 `G` 是一个块。

1. `G` 没有割点。
2. 任意两个不同顶点 `u, v` 之间存在两条**内部顶点不相交**的 `u-v` 路。
3. 任意两个不同顶点 `u, v` 在同一个圈上。
4. 任意顶点 `v` 和任意边 `e` 在同一个圈上。
5. 任意两条边 `e, f` 在同一个圈上。
6. 任意两个不同顶点 `u, v` 与任意边 `e`：存在一条经过 `e` 的 `u-v` 路。
7. 任意三个不同顶点 `u, v, w`：存在一条经过 `w` 的 `u-v` 路。
8. 任意三个不同顶点 `u, v, w`：存在一条不经过 `w` 的 `u-v` 路。

这组结论不需要逐条硬背，但要抓住同一个内核：

> 块中两点之间总有替代路线，所以删除一个中间点不会把它们彻底隔开。

例如第 2 条最能直接解释“没有割点”：两条路除端点外不共享顶点，删掉任何一个内部顶点最多毁掉其中一条，另一条仍在。

### 4. 块如何组织整张图

块把**边**划分成互不重叠的组：每条边恰好属于一个块。教材将“属于同一块”视为边之间的一种等价关系。

两个不同的块：

- 至多共享一个顶点；
- 若共享一个顶点，这个顶点必是原图的割点；
- 一个顶点是割点，当且仅当它属于至少两个块。

把原图的块和割点再画成一张二分图：

- 一侧的顶点代表每个块；
- 另一侧的顶点代表原图的割点；
- 块顶点 `B` 与割点顶点 `c` 相连，当且仅当块 `B` 包含 `c`。

这张图称为**块-割点图（block-cut graph）**。对于非平凡连通图，它是一棵树。它很像“模块 - 连接口”的结构图：块是局部结实模块，割点是模块之间不能失去的连接口。

## 4.1.2 用 DFS 找所有块：DFSBlk

### 1. 任务与总体想法

输入一个无向图，输出它的全部块。教材的 `DFSBlk` 是第 2 章“找割点 / 割边”DFS 的升级版。

仍然维护：

- `disc[u]`：顶点 `u` 首次被 DFS 发现的时间；
- `low[u]`：从 `u` 的 DFS 子树出发，经过树边并至多借一条回边，能回到的最早祖先的发现时间；
- `parent[u]`：`u` 在 DFS 树中的父亲。

新增一个**边栈** `edge_stack`。DFS 中刚发现、但还没有归属到某个块的边都压在这里。

真正的关键不是“压栈”本身，而是这件事：

> 当 DFS 从孩子 `v` 回到 `u`，若 `low[v] >= disc[u]`，那么 `v` 的这片子树无法绕回 `u` 的任何祖先；从边栈顶一直弹到树边 `(u, v)` 的这些边，恰好组成一个完整块。

这就是割点判定 `low[v] >= disc[u]` 的另一面：以前我们记录“`u` 是割点”，现在顺便把这个割点下方刚刚封口的一块边取出来。

### 2. 教材伪代码的执行逻辑

教材的 `DFSBlk` 做了两类修改：

1. 发现树边 `(u, v)` 时压栈；遇到从 `u` 指向祖先 `v` 的回边时也压栈。每条无向边只压一次。
2. 在割点条件成立的地方，不只是标记割点，而是反复弹出边，直到弹出 `(u, v)`；这一批弹出的边就是一个块。

教材从非平凡连通图的某个顶点开始。若 DFS 根不是割点，结束时栈中还会留有一个块，需要额外全部输出。下面的 Python 写法把“边界一出现就输出”写得更直接，结果与教材一致，并额外兼容不连通图与孤立点。

### 3. Python 实现：返回每个块的顶点集合

```python
def find_blocks(graph):
    """
    graph: 无向简单图的邻接表，顶点编号为 0 到 n - 1。
    返回: blocks，其中每个元素是一个块的顶点集合 set[int]。

    例如图 0-1-2-0 再接一条边 2-3，返回的两个块为
    {0, 1, 2} 和 {2, 3}（顺序不保证）。
    """
    n = len(graph)
    discovery = [-1] * n
    low = [-1] * n
    edge_stack = []
    blocks = []
    time = 0

    def output_block_until(stop_edge):
        """从边栈弹边，直到 stop_edge；弹出的边构成一个块。"""
        block_vertices = set()

        while edge_stack:
            a, b = edge_stack.pop()
            block_vertices.add(a)
            block_vertices.add(b)

            if (a, b) == stop_edge:
                break

        blocks.append(block_vertices)

    def dfs(u, parent):
        nonlocal time

        discovery[u] = time
        low[u] = time
        time += 1

        for v in graph[u]:
            if discovery[v] == -1:
                # (u, v) 是第一次看到的树边，暂时归属未定，先压栈。
                edge_stack.append((u, v))
                dfs(v, u)

                # 子树 v 能回到多早，决定了 u 的 low 值。
                low[u] = min(low[u], low[v])

                # v 子树不能绕到 u 的祖先；这里正好封出一个块。
                if low[v] >= discovery[u]:
                    output_block_until((u, v))

            elif v != parent and discovery[v] < discovery[u]:
                # 只处理指向祖先的回边：
                # 否则同一条无向边会从两个方向重复压栈。
                edge_stack.append((u, v))
                low[u] = min(low[u], discovery[v])

    for start in range(n):
        if discovery[start] != -1:
            continue

        # 孤立顶点本身也是一个块。
        if not graph[start]:
            discovery[start] = time
            time += 1
            blocks.append({start})
            continue

        dfs(start, -1)

    return blocks
```

#### 代码和算法逐项对上

- `discovery` 与 `low` 就是教材中的 `d` 和 `low`。
- `edge_stack` 就是教材边栈 `S`。它保存“已走到、但尚未确定属于哪个块”的边。
- 树边先压栈，再递归；回边只在它指向祖先时压栈，这样每条无向边只记录一次。
- `low[v] >= discovery[u]` 时，`(u, v)` 是这一个块最早压入栈的边。持续弹栈到它，刚好得到一个块。

注意：找**割点**时根节点要特判“至少两个 DFS 孩子”。上面的代码找的是**块**，每个根孩子完成时都可能封出一个块，所以不需要在这里单独写 `child_count`。这不是漏掉根的特判，而是任务输出不同。

### 4. 小例子：环加一条尾巴

考虑：

```text
0 ----- 1
 \     /
   2 ----- 3
```

边是 `(0,1), (1,2), (2,0), (2,3)`。从 `0` 出发，DFS 可以走 `0 -> 1 -> 2 -> 3`。

1. 先压入树边 `(0,1)`、`(1,2)`、`(2,3)`。
2. `3` 没有别的出路，所以 `low[3] = disc[3]`。回到 `2` 后，`low[3] >= disc[2]`，弹出 `(2,3)`，得到块 `{2, 3}`。
3. `2` 还看见已发现的祖先 `0`，这是回边 `(2,0)`，压栈；于是 `low[2]` 被更新为 `disc[0]`。
4. 回到 `1`、再回到 `0` 后，`low[1] >= disc[0]`，从栈顶依次弹出 `(2,0)、(1,2)、(0,1)`，得到块 `{0,1,2}`。

顶点 `2` 同时属于两个块，所以它是割点；边 `(2,3)` 自成一个 `K_2` 块，也正是割边。

### 5. 正确性直觉与复杂度

边栈中的边始终来自当前 DFS 还没有“封口”的部分。若 `low[v] < disc[u]`，说明 `v` 的子树能绕回 `u` 的祖先，当前这部分还不能拆开；若 `low[v] >= disc[u]`，它无法跨过 `u` 向上绕路，栈顶到 `(u,v)` 的边正好形成一个必须整体留下的无割点区域。

每个顶点第一次访问一次，每条无向边只会被常数次检查、压栈和弹栈，因此：

- 时间复杂度：`O(n + m)`；
- 空间复杂度：`O(n + m)`，来自 DFS 状态、递归栈和边栈。

初学时最容易错的地方：

1. 把回边也双向压栈，导致同一条边出现两次。
2. 把 `low[v] >= disc[u]` 写成更新 `low[u]` 前后无关的比较，或把 `v` 写成 `u`。
3. 忘记孤立顶点也可以单独构成块。
4. 在 Python 递归很深的题里撞上递归深度限制；真实大图可改迭代 DFS，或在明确可控的环境中调整递归深度。

## 4.2 割集和连通度

### 1. 点割集：删哪些顶点会让图更碎

对顶点集 `S ⊆ V`，删去 `S` 及其关联边后的图记作 `G - S`。若 `G - S` 的连通分支数比 `G` 更多，则 `S` 是图 `G` 的**点割集（vertex cut，也称分离集）**。

割点就是只含一个顶点的点割集。

要区分两个经常混淆的词：

- **极小点割集（minimal vertex cut）**：按包含关系极小。删掉其中任意一个点后，它就不再是点割集。
- **最小点割集（minimum vertex cut）**：顶点数量最少。

“极小”问的是还能不能继续删元素；“最小”问的是大小是否达到全局最优。一个极小点割集不一定最小。

### 2. 点连通度 `κ(G)`

使图 `G` 不连通或变成平凡图，至少需要删去的顶点数称为**点连通度**，记作 `κ(G)`。

- `κ(G) = 1`：有割点。
- `κ(G) = 2`：删任意一个点仍连通，但存在两个点一起删会使图断开或只剩平凡图。
- 若 `k <= κ(G)`，称 `G` 是 **k 点连通图**。

因此 `κ(G)` 不是一个“是否连通”的布尔值，而是网络能承受多少个顶点故障的量化指标。

例子：

- 有割点的连通图：`κ(G) = 1`。
- 圈 `C_n (n >= 3)`：`κ(C_n) = 2`。删一个顶点仍是一条路径；删两个合适顶点可断开。
- 完全图 `K_n`：`κ(K_n) = n - 1`。只要还剩至少两个点，它们仍相连。
- 不连通图：`κ(G) = 0`。

对阶至少为 3 的块，它正是 2 点连通图；但不要反过来把一条边 `K_2` 排除在“块”之外，它是块，却不是 2 点连通图。

### 3. 边割集与边连通度 `κ'(G)`

对边集 `S' ⊆ E`，删去这些边后的图记作 `G - S'`。若连通分支数增加，则 `S'` 是**边割集（edge cut）**。

- 割边就是只含一条边的边割集。
- **极小边割集**按包含关系极小。
- **最小边割集**的边数最少。

使图不连通或变成平凡图，至少需要删去的边数称为**边连通度**，教材记作 `κ'(G)`（很多资料也写作 `λ(G)`）。若 `k <= κ'(G)`，称为 **k 边连通图**。

例子：

- 树中每条边都是割边，所以边连通度为 1。
- 圈 `C_n` 的边连通度为 2：删一条边仍连通，删两条合适的边会断开。
- 平面图的边连通度为 0（教材把“删边后成为平凡图”也纳入定义）。

### 4. 三个量的基本不等式

记最小度数为 `δ(G)`，教材给出：

```text
κ(G) <= κ'(G) <= δ(G)
```

直觉很值得记住：

1. `κ'(G) <= δ(G)`：选度最小的顶点，把它的所有 incident 边删掉，这个点就孤立了；所以不必删超过最小度那么多条边。
2. `κ(G) <= κ'(G)`：删边能让图断开，说明这些边连接了某些区域；删掉适当的端点也可以破坏连接。顶点故障通常比单条线路故障更“猛”，因此需要防住顶点故障的数量不会高于防住边故障的数量。

它们只是上界/下界，不代表每次都相等。给图加边常常会提升连通度，但并非保证严格提升：加的边可能并没有绕开真正的薄弱位置。

## 4.2.2 门格尔定理：删不掉，是因为有多少条独立备选路

### 1. 内部顶点不相交与边不相交

两条 `u-v` 路：

- **内部顶点不相交**：除了端点 `u, v` 外，不共享任何顶点；
- **边不相交**：不共享任何边，但允许经过同一个中间顶点。

前者更强，因为共享中间顶点时，那个顶点一旦失效，两条路会一起断。

### 2. 门格尔定理的点版本

对于图 `G` 中两个不相邻顶点 `u, v`：

> 使 `u` 与 `v` 不连通所需删除的最少顶点数，等于 `u` 到 `v` 之间内部顶点不相交路径的最大条数。

这就是“最少要拆几个中转站”与“最多有几条互不抢中转站的备选路线”完全相等。

由此得到教材的推论：非平凡图 `G` 是 `k` 点连通图，当且仅当任意两点之间至少有 `k` 条内部顶点不相交的路。

这也解释了块的等价刻画：块（阶至少 3）是 2 点连通图，所以任意两点之间有至少两条内部顶点不相交的路。

### 3. 门格尔定理的边版本

对任意两个顶点 `u, v`：

> 使 `u` 与 `v` 不连通所需删除的最少边数，等于 `u` 到 `v` 之间边不相交路径的最大条数。

对应推论：非平凡图 `G` 是 `k` 边连通图，当且仅当任意两点之间至少有 `k` 条两两边不相交的路。

### 4. 从块推广出的结论

教材还给出：对于 `k` 连通图 `G`，任取 `k` 个顶点 `v1, v2, ..., vk`（`k >= 2`），存在一个圈经过这 `k` 个顶点。

它是在说高连通度会强迫图中出现更丰富的绕行结构。注意它**不是**“一定有哈密尔顿圈”：这里只保证经过指定的 `k` 个点，不要求经过全部顶点。

### 5. 连通度如何计算

本章给出的是路线：根据门格尔定理，计算点/边连通度可转化为计算两点之间最多有多少条不相交路径；进一步可归约为**最大流**问题。第 7 章会专门处理最大流算法。

现在先记住转换关系即可：

| 想求什么 | 转化成什么 |
| --- | --- |
| 两点间最小点割 | 最大条数的内部顶点不相交路径 |
| 两点间最小边割 | 最大条数的边不相交路径 |
| 全图点/边连通度 | 枚举顶点对，取相应最小割的最小值 |

对于很小的图，可以直接暴力枚举删除集合来验证定义；这适合理解，不适合大图。

```python
from itertools import combinations


def is_connected_after_removing_vertices(graph, removed):
    """判断删去 removed 中顶点后，剩余顶点诱导的图是否连通。"""
    removed = set(removed)
    remaining = [u for u in range(len(graph)) if u not in removed]

    # 剩余 0 或 1 个顶点时，按点连通度定义视为平凡图。
    if len(remaining) <= 1:
        return True

    start = remaining[0]
    seen = {start}
    stack = [start]

    while stack:
        u = stack.pop()
        for v in graph[u]:
            if v not in removed and v not in seen:
                seen.add(v)
                stack.append(v)

    return len(seen) == len(remaining)


def vertex_connectivity_bruteforce(graph):
    """
    用定义暴力计算 κ(G)，仅用于小图学习与验证。
    时间会随 n 指数增长；大图应在学完最大流后使用门格尔定理的算法。
    """
    n = len(graph)

    # 原图已不连通，连通度为 0。
    if not is_connected_after_removing_vertices(graph, set()):
        return 0

    for size in range(n):
        for removed in combinations(range(n), size):
            remaining = n - size

            # κ(G) 的目标是让图不连通或平凡。
            if remaining <= 1:
                return size

            if not is_connected_after_removing_vertices(graph, removed):
                return size

    return n - 1
```

这段代码的重点不是效率，而是把定义翻译成程序：从删除 0 个、1 个、2 个顶点开始枚举，第一次能使图断开或平凡的数量，就是 `κ(G)`。它也让“最小”和“极小”的差别很直观：这里枚举的是数量，所以求的是**最小**点割集；并没有枚举所有按包含关系极小的集合。

## 本章收束

本章把“连通”升级成“连通得有多稳”。

- **块**告诉你：图的哪些局部没有单点故障；`DFS + discovery + low + 边栈` 能在线性时间把它们拆出来。
- **点/边连通度**告诉你：至少损失多少个顶点或多少条边，图才会断。
- **门格尔定理**给出最重要的对偶直觉：最少要破坏多少资源，等于最多有多少条互不争抢关键资源的备选路径。

以后学匹配、网络流、可靠性分析时，这条“割集 <-> 不相交路径 <-> 最大流”的链会反复出现。先把它记成一个判断问题的方向：**如果题目在问网络能抗几次故障，就去找割集；如果题目在问有多少条真正独立的备选路线，就去想门格尔定理。**
